# Siris — Lưu trữ (ảnh, file, sao lưu Google Drive) và chạy thật

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Chuyển file (ảnh bàn giao, ảnh giấy tờ, mẫu Word, bản xuất) sang Cloudflare R2, tự xoá ảnh sau thanh lý, sao lưu cơ sở dữ liệu mỗi đêm ra Google Drive, rồi chuyển sang dữ liệu thật.

**Architecture:** Tách khỏi [plan chức năng](2026-11-16-chuc-nang.md) ngày 16/11/2026 theo yêu cầu người dùng: test xong các chức năng trước, rồi mới làm phần lưu trữ. Trong lúc test chức năng, file vẫn nằm ở Supabase Storage (bucket riêng tư `siris`, `STORAGE_DRIVER=supabase`) qua lớp adapter của Task 6, nên đổi sang R2 không phải sửa nghiệp vụ. Sao lưu chạy bằng GitHub Actions, độc lập với app.

**Tech Stack:** Next.js 16 (route handler cho cron), Drizzle, `@aws-sdk/client-s3` (R2 tương thích S3), Vercel Cron, GitHub Actions + `pg_dump` 17 + `rclone`, Vitest + PGlite.

**Spec:** `docs/superpowers/specs/2026-11-16-quan-ly-khach-thue-design.md` — §9 (ảnh, R2, thời hạn lưu, sao lưu Google Drive), §10 đợt 5.

**Điều kiện bắt đầu:** Người dùng đã duyệt các chức năng ([plan chức năng](2026-11-16-chuc-nang.md), Phần E). Riêng Task 22 đã làm xong từ trước.

## Global Constraints

- Ảnh bàn giao (check-in, check-out) chỉ giữ **30 ngày sau ngày thanh lý** (`photoRetentionDays`, mặc định 30, cấu hình 1–365); biên bản đã xuất (Word/PDF) và dữ liệu văn bản (tình trạng, tiền phạt) giữ mãi.
- Ảnh giấy tờ tuỳ thân xoá cùng lúc với ảnh bàn giao, **trừ khi** khách còn hợp đồng thuê `active` hoặc cọc `pending`; ảnh sự cố giữ lại.
- Nút **"Giữ lại ảnh"** trên hợp đồng (`leases.keep_photos`) hoãn xoá khi đang tranh chấp.
- File truy cập qua URL ký có hạn 5 phút, sau khi kiểm quyền (route `GET /api/files/[id]`, Task 6).
- Sao lưu: chỉ cơ sở dữ liệu Supabase (gồm schema `auth`), mỗi đêm 2h giờ Việt Nam, giữ **30 bản** gần nhất trên Google Drive; file trong R2 không sao lưu ra Drive.
- Không ghi secret vào code hay commit; secrets đặt ở Vercel / GitHub Secrets.
- Giao diện, tài liệu vận hành và commit bằng tiếng Việt.

## Review Focus

4. **Chép file sang R2 bị ngắt giữa chừng** → chạy lại `scripts/migrate-storage.ts` không chép trùng, không mất file. → Task 21 Step 1.
5. **Bản sao lưu không khôi phục được** → phát hiện trước khi dùng thật nhờ lần chạy thử khôi phục bắt buộc. → Task 22 Step 5.

**Interfaces:**
- Consumes: `StorageAdapter`, bảng `files` (Task 6); `files.delete_after` do Task 15 đặt.
- Produces:
  - Cột `leases.keep_photos bool not null default false`; `setKeepPhotos(db, ctx, leaseId, keep: boolean)` cần `tenants_contracts`, ghi audit.
  - `purgeExpiredFiles(db, storage, today: ISODate): Promise<{ deleted: number; skipped: number; failed: number }>` — với mỗi file `delete_after ≤ today`: bỏ qua nếu hợp đồng gốc bật `keep_photos`; với `tenant_document` kiểm lại lúc xoá: khách còn hợp đồng `active` hoặc cọc `pending` → đặt `delete_after = null`, không xoá; xoá object (chính + thumbnail) trước, thành công mới xoá bản ghi; lỗi object → giữ bản ghi, tăng `failed`. Ghi một dòng audit `purge_files` kèm số liệu. `owner_type = 'export'` không bao giờ bị xoá.
  - Route `GET /api/cron/purge-files`: so header `Authorization: Bearer ${CRON_SECRET}`; sai → 401. Lịch trong `vercel.json`: `"crons": [{ "path": "/api/cron/purge-files", "schedule": "0 20 * * *" }]` (3h sáng giờ Việt Nam).
  - `r2.ts`: `createR2Adapter({ accountId, accessKeyId, secretAccessKey, bucket })` dùng `@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner` (endpoint `https://<accountId>.r2.cloudflarestorage.com`, region `auto`).
  - `scripts/migrate-storage.ts`: duyệt bảng `files`, chép từng object Supabase → R2 nếu R2 chưa có key đó (`HeadObject`), in tiến độ; chạy lại an toàn. Xong thì đổi `STORAGE_DRIVER=r2` trên Vercel.
  - `docs/operations/r2.md`: tạo bucket riêng tư, CORS cho domain app (PUT từ trình duyệt), khoá truy cập, biến `R2_*`, chạy `migrate-storage`.
